# napari-deeplabcut v0.4.0

napari-deeplabcut 0.4.0 is a maintenance release with compatibility and data integrity changes.

> [!IMPORTANT]
> Version numbers now follow PEP 440. This release is `0.4.0`, future ones will continue with this scheme.
> Version resolution and the installation of `deeplabcut[gui]` are unchanged.

## Highlights

- A keypoints layer no longer leaks unrelated image folder info, preventing accidental overwrites; mismatches are now reported (#246, closes #245).
- Keypoints on frames missing from the folder are now reported instead of silently moved (#246)
- Re-opening the same extracted frames folder no longer loads a duplicate keypoints layer (#246)
- Reduced use of napari internals, to help ensure compatibility with upcoming napari releases (#242)
- The `numpy<2` upper bound is released; following DeepLabCut 3.0.2 (#241)
- Layer lifecycle fixes for reattached and recycled keypoint layers (#243)

## What you should know

### Opening a new extracted frames folder with leftover keypoints layers

A partially annotated keypoints layer left open when a different extracted frames folder was loaded
could partially route to that folder and, on the next save, write its annotations into that dataset.
This happened for a different folder in the same project, the same folder name in a different
project, and two folders whose frame names collide entirely.

Now a newly opened folder that does not match the points layer leaves the save routing untouched, reports the mismatch in a dialog instead of accepting silently, and a later save writes back to the layer's own dataset.

**If you label several videos in one session, expect a warning dialog if you leave leftover points layers** It means the layer and the folder are different datasets;
clear the layers before opening the next folder as instructed, and drag-and-drop `config.yaml` to get a fresh keypoints layer.

Frames renamed or re-extracted inside the *same* folder give a softer message when none of them match any more: the annotations are unchanged and still save in that folder, with no advice to clear the layers.
If some frames still match but an annotated frame is gone, see the next section.

### Frames deleted or renamed after labeling

If an annotated frame is no longer in the folder (renamed or deleted),
the positional indexing would drift, causing keypoints to be associated with the wrong frames.

The plugin now refuses the match and reports it instead.

**Annotation files are not modified when this occurs**, the plugin refuses rather than rewriting anything.
The layer keeps the keypoints it loaded.

Because the layer stays on its own frames, keypoints after the missing one may display one
frame off. **Do not re-place them while this message is showing.**

**To resolve it**, put the frame back in the folder, or drop its row from
`CollectedData_<scorer>.csv` and rebuild the `.h5` with `deeplabcut.convertcsv2h5`.

### Opening the same folder twice with leftover keypoints

Opening a folder re-reads its annotation file, so opening one twice used to create two identical
keypoints layers, both saving to the same file. The second copy
is now closed, with a notification.

### napari UI compatibility

Two behaviours that previously failed quietly now notify once per session: when napari's
native point-size controls cannot be hidden, and when the keypoint paste shortcut cannot
be installed. Both indicate a napari version whose layer controls the plugin does not
recognize; the plugin stays usable, please report if you see either.

## Bug fixes

- #246 — Fix a keypoints layer adopting an unrelated dataset and saving into it (#245)
- #243 — Fix keypoint layers keeping bindings to a previous store after reattachment, and
  a recycled layer id being refused registration because a collected layer left it behind
- #243 — Fix the placeholder-config choice being discarded when closing was cancelled,
  which made a later config merge fall back to the default action
- #246 — Reject a folder whose frames match only by filename, which any two dataset
  folders in a DLC project do
- #246 — Stop keypoints on a deleted frame being re-keyed onto another frame, which copied
  them one frame further down the folder on every save

## For developers

### NumPy 2 (#241, #247)

The core `numpy<2` bound is removed, following the same effort in DeepLabCut
(DeepLabCut#3499). Worth watching: DeepLabCut's TensorFlow extras still cap NumPy below 2
on some Python versions, so the NumPy actually resolved inside a `deeplabcut[gui]`
environment depends on which extras are installed, not on this plugin alone.

### napari compatibility canary (#239, #249)

A weekly job now runs the suite against `napari --pre` and against the declared 0.6.6
floor and latest stable, and opens a tracking issue on failure. The release path builds
the distribution once and publishes the artifact that was installed and tested.

### Faster test suite (#237)

The suite runs under `pytest-xdist` (`-n auto --dist loadfile`), roughly 290s to 60s
locally.
